# 配布形式とセキュリティ警告への対応

## 配布構成

最初のダウンロードをセットアップexeひとつにまとめ、標準NSISのセットアップとネイティブWin32のアプリ起動器を使用する構成です。通常のアプリ起動でPyInstallerの自己展開は行いません。セットアップ画面は同梱のPythonから起動し、導入先、Windowsへの登録、任意の録音・AI環境を選べます。

ユーザーが別途Pythonを導入する必要がないよう、GUI・従来方式用と方式②・録音用のランタイムを同梱する設計です。保守画面では、検証したセットアップをインストール先の外へコピーして起動し、元の起動元の終了を待ちます。削除対象のリンク先の保護、更新前のハッシュ確認、失敗時の復旧を行います。

## 警告の種類

| 表示の例 | 確認するもの |
| --- | --- |
| 「WindowsによってPCが保護されました」「認識されないアプリ」 | SmartScreenによるファイル・発行元の評価。署名済みの新しいアプリでも表示されることがあります。 |
| 「Trojan:Win32/...」等の検出名、隔離・削除 | ウイルス対策製品の検出名・対象ファイル・日時。 |
| ブラウザーのダウンロード警告 | ダウンロード元、対象ファイルと製品の検出内容。 |

## 検証状況

配布物ごとに、Windowsでのビルド・実インストール・修復・削除、録音と認識環境、Defender検査などを確認します。具体的な結果は各ビルドのワークフローと成果物を参照してください。検査できない状態や異常終了を「未検出」として扱いません。検査前後の対象ファイルのSHA-256も照合します。1つの環境で未検出でも、他社製品や別の定義で警告が出ない保証にはなりません。

警告が続く場合は、製品名・検出名・対象のSHA-256に基づいて確認し、必要に応じて提供元の解析窓口へ申告します。ウイルス対策の無効化や除外登録を解決方法にせず、検出を避けるためだけにファイルを改変しません。公開解析サービスへ配布物を自動アップロードする処理も設けていません。

セットアップexeにはAuthenticode発行元署名を付与していません。公開タグのGitHubビルド出所証明は、Windowsの発行元署名やウイルス検査とは別です。出所証明を確認できない更新の自動実行は拒否します。第三者ソフトウェアと再配布条件の確認事項は [第三者ソフトウェアの情報](../../THIRD_PARTY_NOTICES.md) を参照してください。
