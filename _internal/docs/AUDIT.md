# ファイル・安全性の点検記録

## セットアップと音声環境

FFmpegの配置は、Windowsエラー5・32・33だけを時間制限付きで再試行します。各試行で元ディレクトリの同一性、祖先のリンク／ジャンクション拒否、移動先の不在と固定バイナリーのSHA-256を再確認します。権限やウイルス対策設定は変更しません。提供されたエラーはディレクトリ移動の拒否を示しますが、拒否したプロセスや恒久的なACLが原因かまでは特定できません。

DocumentsはWindows Known Folder APIを優先し、OneDriveなどのリダイレクトも反映します。設定はインストール先に残し、ユーザー出力の保存先だけを変更します。既存の個別保存先と出力ファイルを自動移動・削除しません。子プロセスの出力はシェルを介さず明示的なパイプで取得し、認証トークンを伏字にして記録します。

②・録音用のPython 3.14.10は公式PSFの固定NuGetパッケージをサイズ・SHA-256で検証し、安全なメンバーを展開します。実行前にPSF実行ファイルの発行元署名をWindowsで検証し、Microsoft署名済みのアプリローカルCRTを配置します。古いSQLite・XZをそのまま追加しないよう、固定したSQLite 3.53.4とXZ 5.8.4への差し替え／再ビルドを行い、実際の版と動作を検査します。設定・モデル・出力とは独立した仮想環境を構築し、Python版が変わる場合は新環境の読み込み確認後に切り替えます。

CUDAのDLLは専用仮想環境のTorch配下に限定し、リンク／ジャンクションや外部から先に読み込まれた同名DLLを拒否します。絶対パスで読み込み、実際の読み込み元を照合し、遅延読み込み用ハンドルを保持します。CTranslate2が外部の`CUDA_PATH`を参照しないよう、そのエンジンプロセス内だけで除去し、CWDや一般のPATHを使わないDLL探索を設定します。CPUや他のプロセス、Windows全体の環境変数は変更しません。CUDA用wheelのWindowsネイティブ読み込みと、実際のGPUでの演算・認識は別の検査です。

同じPython版の環境に対する将来のライブラリ更新は直接更新であり、すべてのpip更新が完全にトランザクション化されているという保証ではありません。依存ライブラリが未対応のPython版を無理に採用しません。取得・署名・互換性の実検証結果は、該当コミットのWindows CIと`DEPENDENCIES.json`・`WINDOWS_SMOKE.json`で確認します。

## 点検範囲

ソースと配布対象ファイルについて、全テキストの機密情報・古い案内の検索、Pythonの構文木によるシェル実行の検査、設定読込・ダウンロード・モデル取得・ファイル更新・ログ・CSVの処理を重点的に確認しました。

- 点検では、実際のHugging Face／GitHubトークンや秘密鍵は検出しませんでした。テスト内の偽トークンと一般的なサンプル名は検証用です。新しい配布物も個別に点検してください。
- PNGのメタデータにEXIF・位置情報・撮影者情報は検出しませんでした。アイコン300件の透明度情報は表示に必要なものです。
- SVGにはスクリプト、イベントハンドラー、外部画像参照を検出しませんでした。
- 実行コードに`os.system`、`shell=True`、外部文字列の`eval`実行は検出しませんでした。テスト内の`exec`は、同梱の固定起動スクリプトを検証するために使っています。

機密情報が将来の録音・任意保存先・ログ・設定書き出しへ混入しないことを保証する検査ではありません。利用者が作成したデータは配布物から除外します。

| 検出した点 | 対応・確認内容 |

| 存在しない旧セットアップBAT名がエンジンのエラー案内に残る | 現在の「一括セットアップ…」「CUDA診断…」へ案内を統一。 |
| D&D取得の通信名と診断ZIPの案内が旧バージョンで固定されている | 現在のアプリバージョンを参照するよう修正。 |
| ユーザーのpip設定や環境変数で取得元・導入先が変わり得る | Python・pip用の環境変数を除去し、設定ファイルを無効化。pipの隔離モードと仮想環境限定の導入を使い、PyPI・PyTorch公式の取得元を明示。互換性のある方式ではwheelを限定使用する。 |
| 標準のAIモデルキャッシュがアプリフォルダー外へ作られる | インストーラーが作成したポータブル設定を確認して、同梱ランタイム・モデル・設定の保存先をアプリ内へ統一。既存の共有キャッシュは勝手に削除しない。 |
| 新しいインストール処理でも復旧失敗時のバックアップ消失が起こり得る | 途中までの変更を全件復旧し、失敗した場合はバックアップと復旧用の記録を保持する処理へ修正。 |
| 検証後に元の更新ZIPが変更されると、検証した内容と展開する内容が異なり得る | 容量を制限して一時ファイルへコピーし、その同じスナップショットのSHA-256を照合してから展開する。差し替えを模擬したテストも追加。 |
| WindowsのPython割り当てへバッチファイルが混入すると、シェルによる引数解釈が起こり得る | Python割り当ての`.bat`・`.cmd`を拒否し、文字起こしプロセスへ渡さない。 |
| オフラインのビルド証明はリポジトリ名だけの照合では不十分 | 証明の証明書に記録されたリポジトリIDを、インストール時に固定したIDと照合。別リポジトリが同名を使った場合の証明を拒否。 |
| Pythonの「3.11系」指定だけでは、古いWindowsバイナリーがビルド元に選ばれ得る | 公式CPython 3.11.18のソースと周辺依存の入力を固定し、配布用・ビルド試験用の両方を同じWindowsソースビルドへ切り替える構成。実際の生成物・ネイティブ試験の成功は該当コミットのCI結果で確認する。 |
| 閉じたGUIへの変数監視やテストの循環参照が残り、音声ワーカーのGCでTkオブジェクトが解放され得る | 画面破棄時に変数監視・タイマーを解除。GUIテストもアプリ・ダイアログ・モック・コールバックの参照を解放してから所有スレッドで回収し、その後のワーカーGCにTkオブジェクトを残さない回帰確認を追加。 |
| Windowsの短縮名（8.3名）と通常名で、同じインストール先やキュー項目のパス表記が異なる | インストール先を正規化し、保守exeの同一性・記録・排他に同じパスを使用。正規化前後のリンク・ジャンクション拒否は維持。GUI試験の入力元も正規形へ統一し、別表記入力の重複排除を確認する。 |
| 古いファイル日時をWindowsでローカル時刻へ変換すると例外になる場合がある | UTCのタイムゾーン付き日時からローカル時刻へ変換し、範囲外・取得不能な日時は未取得として扱う。TXT／CSV内の録音日時を優先する動作は維持。 |
| 選択欄のTcl側ポップアップから別の欄へ移ると、選択欄自体にフォーカス喪失通知が届かない場合がある | 移動先のフォーカス取得でもクリック済み状態を解除し、フォーカスを外した選択欄がホイールで変わることを防ぐ。自分のポップアップへ移る場合はクリック済み状態を維持。 |

バックアップ保持、出力・CSV復旧、D&D、更新処理のセキュリティテストを用意しています。更新テストでは不正URL、圧縮応答、サイズ違い、重複JSON、ハッシュ不一致、署名欠落・不一致、証明内のリポジトリIDの欠落・不一致などを拒否することを確認しています。全体のテスト結果とWindows実機確認の範囲は[検証範囲](VALIDATION.md)を参照してください。

インストール・ポータブル環境・不正な設定・pip設定分離・ビルド・起動の関連テストを実行しています。全体の件数と実行環境は [検証範囲](VALIDATION.md) に記録し、Linux上の結果とWindowsネイティブAPIの結果を区別します。

旧バージョン番号が残るテスト名・CSV形式識別子・移行元設定名は、互換性確認に必要な場合があります。現在の画面案内と、保存済みデータを読み込むための識別子を区別して点検しています。

## 更新機能で確認する境界

更新は、通常の音声・CSV・設定ファイルの読み込みよりも強い権限で、アプリの実行ファイルを置き換えます。公開GitHubの決まったリポジトリから取得し、次の境界を確認します。

- HTTPSと取得先のホスト・リポジトリ・タグ・ファイル名を限定し、ダウンロードのリダイレクト先も検証する。
- 通信のタイムアウトとJSON・ダウンロード・展開後のサイズ上限を設け、途中・破損・想定外のファイルを実行しない。
- GitHubが返すリリース資産のSHA-256と、実際に受信した全バイトを照合する。ハッシュ値のない資産は自動適用しない。
- 更新候補を別の場所で検証し、アプリ停止後に置き換える。失敗時は旧版へ復旧する。
- 絶対パス、`..`、Windowsの別データストリーム・予約名、重複パス、シンボリックリンク、ジャンクション等を拒否する。設定・モデル・録音を更新アーカイブに上書きさせない。
- ダウンロードした本文をPythonやPowerShell等のコードとして実行しない。外部文字列をシェルコマンドへ連結しない。
- アクセストークンをクライアントへ埋め込まない。プライベートリポジトリは公開向けの認証なし更新で取得できないため、その状態を利用者へ示す。

GitHub APIのダイジェストは、取得したファイルの完全性を確認するものです。この実装では、それに加えて署名付きビルド証明の検証を必須にし、署名者・リポジトリID・ワークフロー・タグ・GitHubホスト上の実行元を限定します。署名のないリリースへハッシュだけで自動更新することはありません。

これらはGitHubのリリース権限やビルド元そのものが侵害された場合まで安全にする保証ではありません。初回配布exeのAuthenticode署名と、管理者認証・リポジトリ権限の制限は別の対策です。プライベートで作成したリリースには公開向けのビルド証明を付けないため、公開したタグからの証明付きリリースを作成するまでは、自動更新の正常系を実際の公開リリースに対して確認できません。

ソース反映用のワークフローも確認しました。明示的に指定した候補ZIPのSHA-256を照合し、既存の`.github`を同じ内容で保持します。現在のコミットを親とする通常のコミットを作成し、ブランチが開始時から変更されていないことを確認して反映します。この段階ではタグを作成せず、Windowsでビルドと検証が成功した後にリリース用タグを作成します。履歴を新しいルートへ置き換えません。

Windowsの配布前テストには、実際のHKCUアンインストール登録・COMによるスタートメニュー登録と解除、NTFSジャンクションの先にあるファイルを消さないことの確認を追加しています。対象は一時フォルダーと一意のインストールIDに限定し、失敗時も登録を解除する設計です。実際の成功結果はWindowsのビルド記録で確認します。

保守exeの再起動では、起動元が終了済みでも別の起動元にプロセスハンドルが残る場合を扱います。同じハンドルのシグナル状態で終了を判定し、実行中の場合は従来どおりアプリの固定パスを検証して待機します。確認に失敗した状態を、終了済みとして扱いません。

exeへ書き込むバージョン情報とアイコンは、配布形式に応じた生成・読み込みを検査します。セットアップ画面のアイコン画像は元のフォルダー構成で同梱し、実際のexeの自己検査でも透明な代替画像ではないピクセルを読み込めることを確認します。

## 配布Pythonの取得・ビルド

CPython 3.11はセキュリティ修正をソースで配布する段階にあるため、古い公式Windowsインストーラーのコピーを新しいランタイムとして扱いません。CPython 3.11.18の公式ソースを、事前に固定したSHA-256と照合してWindows用にビルドする構成です。配布用のPythonに加えて、ビルド・試験用環境も同じ3.11.18のビルドから作成します。アプリ起動器はネイティブWin32、セットアップはNSISで生成し、PyInstallerは使用しません。

周辺依存も取得先・版・ハッシュを固定します。今回の構成では、すべての依存をソースから生成するわけではありません。

| 構成 | 取得・組み込み方 |
| --- | --- |
| CPython 3.11.18 | Python公式のソースからWindows x64用にビルド。配布用とビルド・試験用の両方に使用。 |
| Tcl/Tk 8.6.18 | Tcl/Tk公式リポジトリの固定コミットからビルド。Tclに同梱されるzlib 1.3.2のDLLは、同じ固定アーカイブ内の既製バイナリーを使用。 |
| SQLite 3.53.4、XZ 5.8.4、zlib 1.3.2、bzip2 1.0.8 | 公式配布元またはCPython公式依存リポジトリのソースからビルド。XZの旧版アーカイブから使うのはWindows用の設定ヘッダーだけで、旧版のCソースはコンパイルしない。 |
| OpenSSL 3.5.9、libffi 3.4.4 | CPython公式依存リポジトリの固定されたWindows用バイナリーを使用。 |
| pip 26.2.2、setuptools 84.2.1 | 固定したPyPI wheelをensurepipに同梱。 |

[Pythonの固定入力](../tools/cpython-windows-sources.json)、[配布ツールの固定入力](../tools/windows-build-sources.json)、生成物の版とビルド時の調整を記録する `DEPENDENCIES.json` を参照してください。同じ入力情報は、インストール先の `_internal/distribution-info.json` にも記録します。ハッシュを固定することは、その入力の無害性や将来の脆弱性不在を証明するものではありません。

WindowsのVisual C++ランタイムは、必要なx64 DLLが揃っていることと、Microsoftによる有効なAuthenticode署名を、ビルドの初期段階で確認します。証明書ストアの変更、署名検査の回避、システム全体へのランタイムインストーラーの実行は行いません。ソース・依存の確認と、生成したPythonのTk・SSL・venv等が実際に動作したかの確認は分け、後者はWindowsのネイティブビルドとスモークテストの結果で判定します。

コンパイル済みPythonのキャッシュは、非公開リポジトリのmainに対する手動ビルドだけで使用します。キーはリポジトリID、Windowsイメージ版、ホストPython、ビルド処理・固定入力・ワークフロー等に結び付け、完全に一致しない候補は破棄してソースから生成します。保存対象はPythonランタイムとビルド記録に限り、モデル・設定・認証情報・追加のpip環境は含めません。新規生成時のSSL回帰を含むネイティブ確認に成功してから保存し、再利用時は信頼済みホスト側の処理で全ファイルの集合・容量・SHA-256と固定入力を実行前に照合します。さらに現在のMicrosoft CRT署名とキャッシュ内のCRTのバイト一致を確認し、ネイティブ動作確認も繰り返します。

キャッシュ目録は破損・不一致の検出用で、キャッシュ作成者を独立に認証する署名ではありません。作成者の信頼はGitHubの非公開mainへの書き込み権限とキャッシュの適用範囲に依存します。公開リポジトリやタグからのビルドはこのキャッシュを使用せず、毎回ソースから生成します。公開配布の出所証明に、非公開キャッシュの生成物を持ち込みません。

配布するアプリexe・セットアップexe自体にはAuthenticode署名を付与していません。公開GitHubタグの署名付きビルド証明は、リポジトリ・ワークフロー・タグに結び付いた出所を検証する仕組みです。Windowsの発行元署名、初回手動ダウンロード時の信頼判断、依存ライブラリの脆弱性管理は、それぞれ別の確認です。現在のプライベート配布では公開向け証明を生成せず、証明がない更新の自動実行を拒否します。

## 配布形式とセキュリティ警告

標準NSISのセットアップと、ネイティブWin32のアプリ起動器を使用します。セットアップの画面・設定保持・トランザクション・保守用の照合は既存の処理を継続し、NSISから起動された親プロセスと同梱実行環境を確認して開始します。アプリの通常起動では、毎回のPyInstaller自己展開と起動器用Pythonの重複をなくします。

比較用のセットアップと本アプリの旧版は、どちらも実ファイルにAuthenticode署名領域がありませんでした。署名の有無だけでは、利用者が報告した警告の違いを説明できません。確認した配布形式、警告の種類、検証範囲は [PACKAGING.md](PACKAGING.md) を参照してください。

配布前のWindows Defender検査を追加し、検査できない状態を未検出として扱いません。除外登録、ウイルス対策の無効化、検出を避けるためだけのファイル変更は行いません。実NSIS・ネイティブ起動器・移行fixture・修復・削除・追加媒体試験に加えて、生成exeとpayloadをDefenderで検査する構成です。公開用の新しい配布物は別途検証します。SmartScreenや他社製品での警告がなくなることは保証しません。

## WindowsのFFmpeg／FFprobe

点検では、Windows用imageio-ffmpeg 0.6.0のwheelにFFmpeg 7.1が含まれることを確認しました。Pythonパッケージの版が新しくても、同梱のメディア処理バイナリーまで新しいとは限りません。FFmpeg上流では、その後の版でメディア解析のメモリ安全性に関わる脆弱性を修正しています。本アプリを使った任意コード実行が成立すると実証したものではありませんが、古い処理系を使い続ける構成を見直しました。

Windowsメディア処理は、アプリが管理するFFmpeg／FFprobe 9.0.2の組を使用します。取得元は、[FFmpeg公式のWindows配布案内](https://ffmpeg.org/download.html)から参照される[GyanのWindowsビルド](https://www.gyan.dev/ffmpeg/builds/)です。FFmpeg上流が自ら配布したWindows実行ファイルではなく、第三者によるビルドです。[固定入力](../ffmpeg-windows-sources.json)に版・URL・アーカイブのSHA-256を記録し、両実行ファイルもアプリ内の固定ハッシュで照合します。書き換え可能な導入記録だけを信頼の根拠にはしません。

Windowsでは、旧imageio-ffmpeg内の実行ファイルや任意のPATH上のツールを代わりに自動実行しません。検証済みの組がない場合は、録音・録画または認識方式のセットアップによる修復へ案内します。既存の環境が正常でも再セットアップで現在のツールを検証・導入し、モデルや設定は保持します。保存先はアプリ内の `_internal/environments/media-tools` です。

取得したアーカイブと固定値の一致は、FFmpeg上流のソース署名やGyanのデジタル署名を検証したこととは別です。Gyanのビルド元・配布基盤への信頼も残り、依存するすべてのコーデックに将来の問題がないと保証するものでもありません。上流の修正状況は[FFmpegのセキュリティ情報](https://ffmpeg.org/security.html)を参照し、実際のWindows検証結果は[検証範囲](VALIDATION.md)に記録します。

## 直近の圧縮ライブラリの問題

Google Brotliの公式v1.2.1リリースは、細工された圧縮データの復号処理に関わるCVE-2026-111497の修正を案内しています。GitHub AdvisoryではPyPIのBrotli・brotlicffiの影響範囲も示されています。

更新確認・取得は圧縮を必要としないJSONとバイナリーとして扱い、`Accept-Encoding: identity`を指定し、想定外の`Content-Encoding`を拒否します。更新機能のためにBrotli等の追加復号ライブラリを導入する必要はありません。

任意のAI・録音環境のセットアップには、`Brotli>=1.2.1`・`brotlicffi>=1.2.1.0`の制約を追加しました。以前からある環境に古いパッケージが残る場合も、ネイティブ復号処理を読み込まずにバージョン情報を確認し、選択した環境内で更新します。依存していない圧縮パッケージを新規に導入する処理ではありません。

アプリ本体にBrotliの直接依存は検出しませんでした。ただし、任意で導入するAI環境や利用者が以前作成したPython環境の全依存パッケージを、このソース検査だけで安全と判定することはできません。

## AI環境に残る確認事項

従来のセットアップが使用していたPyTorch 2.8.0には、公式アドバイザリーGHSA-63cw-57p8-fm3p／CVE-2026-24747の対象となるチェックポイント読込処理があります。影響範囲は2.9.1以下、修正版は2.10.0以降で、`weights_only=True`でも細工されたモデルを安全に読み込める保証はありません。これは通常の音声ファイルだけで発生する問題という意味ではなく、モデルのチェックポイントを読み込む際の問題です。

最小構成の方式②（faster-whisper＋Resemblyzer）は、同梱Python 3.14.10とPyTorch 2.14.1／TorchAudio 2.11.0を使用し、この問題の修正を含む版へ更新します。Windowsのビルド・検証では、仮想環境の移行、CPU上の話者埋め込み・クラスタリング、CUDA版パッケージと製品のDLL初期化を確認します。GPU推論や大きなASRモデルによる認識を検証した結果ではありません。すでに旧版の方式②環境がある場合は、アプリ本体の更新だけでAI環境も更新済みとは限らないため、「一括セットアップ…」で方式②のセットアップを再実行してください。

他の従来方式は、既存の認識機能との互換性を保つため2.8.0を使用し、このチェックポイント読込の問題が残ります。AI環境の問題もすべて解消したと扱うことはできません。信頼できる配布元以外のモデルや`.pth`・`.pt`・`.ckpt`を持ち込まないでください。TorchAudioは2.9で一部のAPIを削除しているため、旧pyannote方式の互換性を確認せずに一括で置き換えることも避け、今後各方式の依存更新と実際の認識を確認する必要があります。アプリの起動・更新機能自体は、これらのAIライブラリを読み込みません。

## CSV・設定・データの扱い

文字起こしのCSVは、本文や話者名を無損失で保存します。先頭が`=`、`+`、`-`、`@`などのセルは表計算ソフトが数式として解釈する場合があります。外部から受け取ったCSVはダブルクリックで開かず、Excelのデータ取り込み等で列を文字列として指定し、外部リンクや数式の実行を許可しないでください。本文を黙って書き換える対策は、情報保持CSVの往復変換を壊すため採用していません。

設定の書き出しには保存先の情報が含まれます。認証トークンを含める操作は明示的な選択が必要です。共有用JSON・ログは、配布ソースとは別に内容を確認してください。Windowsユーザーの環境変数へ登録した既存の`HF_TOKEN`、アプリ外の保存先、既存の共有モデルキャッシュは、アプリを削除しても残る場合があります。

## 検査の限界

本記録は、ソース・配布対象ファイル・自動テストに基づく確認です。すべての脆弱性が存在しないという認証、侵入試験、Windows上の全音声デバイス・GPUモデルの実測を意味しません。外部依存は、実際に解決したバージョン・配布物・SBOMと最新のアドバイザリーをビルド時および更新時に確認する必要があります。
